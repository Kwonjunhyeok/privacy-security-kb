# 설계: 정보보호·개인정보보호 상담 에이전트

작성일: 2026-11-01

## 목적

실무자가 가져온 정보보호·개인정보보호 관련 주장이나 자료의 진위를 판정하고, 관련 법 조항·ISMS-P 보호조치·가이드·처분 사례를 연관 지어 분석한다. 근거는 항상 현행 공개 자료이며, 매일 최신 상태로 유지한다.

## "학습"의 구현

모델을 재학습할 수 없으므로, 검증을 거친 현행 자료를 담은 지식베이스(`kb/`)를 매일 갱신하고 상담 에이전트가 답하기 전에 이를 읽는다. 개정이 확인되면 구버전 본문을 지우고 현행본으로 교체하며, 변경 사실만 `kb/CHANGELOG.md` 에 한 줄 남긴다.

## FACT_CHECK 2단계

1. **수집 시점**: 수집과 검증을 다른 에이전트가 맡는다. 검증기는 수집기가 본 URL에 기대지 않고 1차 출처를 직접 다시 열어 값 하나하나를 대조한다. A 등급 출처 2곳 이상이 일치해야 통과한다(위협·동향은 1곳). 실패하면 `_pending` 에 격리하고 다음 날 재검증하며, 3회 실패 시 기각한다.
2. **답변 시점**: 상담 에이전트는 답의 모든 사실 진술을 `verified` 가 붙은 kb 문서에 연결한다. 연결할 근거가 없으면 빼거나 `확인 불가` 로 표시한다. kb 에 없는 최신 사안은 1차 출처를 직접 확인한 경우에만 답하고 그 사실을 밝힌다.

## 규정 적합성 검토 모드 (2026-11-02 추가)

상담 에이전트가 사내 규정집·지침을 조항별로 현행 법령·고시·ISMS-P 와 대조한다. 판정은 적합 / 부분 적합 / 부적합 / 누락 / 해당 없음 / 확인 불가. 결과는 요약표, 조항별 판정표, 누락 항목표, 개선 제안(실무 의견), 근거 순으로 고정한다.

- 내부 문서는 이 저장소 밖(예: `D:\Jun\사내규정검토\`)에 둔다. 저장소의 `.gitignore` 가 PDF·DOCX·HWP 등 문서 형식을 막아 실수로 push 되지 않게 한다.
- 내부 문서 문구는 웹 검색어에 넣지 않는다. 웹에는 공개 기준(법령명·조문·ISMS-P 항목)만 조회한다.
- 누락 점검 목록은 기억이 아니라 kb 의 현행 문서에서 뽑는다.
