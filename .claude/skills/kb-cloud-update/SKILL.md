# 클라우드 kb 최신화

이 스킬은 클라우드 세션에서 `UPDATE.md` 절차를 돌리되, main 에 직접 쓰지 않고 PR 로 반영하는 변형이다. 원칙은 `CLAUDE.md` 가 우선한다(검증된 것만 kb, 현행본만, 1차 출처, 지어내지 않기, 원문은 브라우저로).

범위 인자: `$ARGUMENTS` — 비어 있으면 "이월"(최신 보고서의 "다음 실행 이월" 항목)로 시작하고, 사용자에게 전체로 넓힐지 묻지 말고 이월을 끝낸 뒤 보고에서 제안한다.

## 하지 않는 것

- main 에 직접 push, PR 병합(사용자 승인 사항)
- PC 경로(`D:\…`) 작업, 원본 PDF 보관(구글 드라이브 포함), 에이전트 사본 복사 — 로컬 세션 담당
- 원본 PDF 를 저장소에 넣기(.gitignore 가 막는다). 임시 파일은 스크래치패드에만 둔다
- 같은 주 PC 수동 갱신과 동시 실행(PC 는 클라우드가 실패했을 때만 돌린다)

## 0. 사전 점검 (하나라도 걸리면 멈추고 알린다)

1. **중복 실행**: `git fetch origin main` 후 `origin/main` 의 `kb/reports/` 최신 파일 날짜와 `kb/index.md` 맨 위 `마지막 갱신:` 을 본다. 오늘(KST, `TZ=Asia/Seoul date +%F`) PC 갱신이 이미 반영됐거나, 최근 1시간 안에 main 에 kb 커밋이 들어오고 있으면 진행 중으로 보고 멈춘다.
2. **작업 트리**: `git status --short` 가 비어 있지 않으면 이전 중단분이다. 무엇인지 보여 주고, 같은 범위의 미완 작업이면 이어서, 아니면 멈춘다.
3. **브랜치**: 세션이 지정한 개발 브랜치가 있으면 그것을, 없으면 `kb-update/<TODAY>` 를 최신 `origin/main` 에서 만든다(`git checkout -B <브랜치> origin/main`). 지정 브랜치의 PR 이 이미 병합됐으면 최신 main 에서 다시 시작한다.
4. **네트워크**: 브라우저로 출처가 열리는지 1회 확인한다.
   ```bash
   NODE_PATH=$(npm root -g) node scripts/browser/page.js <스크래치패드>/probe "https://www.pipc.go.kr/np/" "https://www.kisa.or.kr/401" "https://www.boho.or.kr/"
   ```
   모두 실패하면 세션 환경이 `privacy-security-kb`(국내 기관 허용 호스트, `pipc.go.kr` www 없는 주소 포함)가 아닌 것이다. 환경 문제라고 알리고 멈춘다. WebFetch 는 국내 기관 사이트에서 실패하므로 판단 근거로 쓰지 않는다.

## 1. 범위 정하기

| 인자 | 할 일 |
|---|---|
| 이월 | 최신 `kb/reports/*.md` 의 "다음 실행 이월"·"보류" 항목과 `kb/_pending/` 의 기존 초안 |
| 전체 | `UPDATE.md` 0~6단계 전부 |
| 개인정보위 안내서 / KISA 가이드 / 보호나라 / 국가사이버안보센터 | 해당 기관 목록 문서(`kb/pipc/pipc-guides-current-list.md`, `kb/guides/*-current-list.md`)를 게시판과 다시 맞추고 새 판·새 자료 요약 |
| 법령 / 위협 | `kb-collector` 범위(법령·고시·처분 / 보안공지·동향) |

처리량은 `UPDATE.md` "사용량 한도 대비"를 따른다(검증 최대 25건, 새 수집 최대 20건, 개별 요약은 한 에이전트당 5건 안팎). 넘는 것은 이월로 적는다. `isms-p.kisa.or.kr` 이 필요한 항목은 이 환경에서 열리지 않으므로 바로 이월로 적는다.

## 2. 수집 (초안은 kb/_pending/ 에만)

- 법령·고시·처분·위협 → `kb-collector`, 가이드·안내서·목록 → `kb-guide-curator` 서브에이전트에 맡긴다. 둘 다 Sonnet 이다(정의 파일). 모델 배정은 `UPDATE.md` "모델" 표를 따른다.
- 프롬프트에 반드시 넣을 것: 오늘 날짜, 대상 목록, 작업 폴더(스크래치패드 아래 `curate_<범위>/`), "kb/_pending 밖 수정 금지", "원문을 직접 연 값만, 못 본 값은 확인필요", 이미 `_pending` 에 있는 초안과 중복 금지.
- 서로 독립인 범위는 에이전트를 나눠 동시에 돌려도 된다(같은 파일을 만지지 않을 때만).

## 3. 검증 (수집과 다른 에이전트)

- `kb-fact-checker` 서브에이전트(또는 그 정의 파일을 그대로 따르게 한 범용 에이전트)에 맡긴다. 법령·고시·ISMS-P·가이드 요약은 Opus(정의 파일 기본값), 보안공지·처분 보도자료 묶음은 Agent 호출에 `model: "sonnet"` 을 준다. 수집 쪽 스크래치 폴더는 열지 말고 원문을 직접 다시 받게 한다(`verify_<범위>/`).
- 지시에 넣을 것: 게시 정보·첨부 해시·쪽수·표지·목차·조문 번호·수치는 전수, 장별 요지는 장마다 최소 1곳 원문 대조, 못 본 장은 "원문 미확인"으로 두고 "게시 정보 + 일부 본문 검증"으로 통과 가능. 법적 의무 문장은 `kb/laws/` 현행 조문과 대조(안내서가 옛 조문을 인용하면 현행 조문을 병기). `## 연관` 에는 kb 에 실제 있는 문서만.
- 문서 하나를 끝낼 때마다 그 파일 수정을 마치고 다음으로 넘어가게 한다(한도로 끊겨도 끝난 것은 남도록).

## 4. 반영 (통과·수정 후 통과만)

각 통과 초안에 대해:
1. `candidate.target_path` 로 내용을 옮기면서 frontmatter 의 `candidate:` 블록과 `fact_check:` 줄, 본문의 `## 보류 사유` 절을 지운다(`## 검증 기록` 은 남긴다).
2. `git rm -f kb/_pending/<초안>` (검증자가 수정한 파일이라 `-f` 가 필요하다), `git add <target>`.
3. `kind: revision` 이고 `replaces` 가 다른 파일명이면 이전 파일을 `git rm` 하고, `kb/` 전체에서 옛 파일명을 새 파일명으로 바꾼다.
4. `kb/catalog.md`: 해당 자료 행의 링크를 kb 문서로, 요약 `목록만` → `있음`, 판이 `확인필요` 면 채운다. 새 기관 목록은 "기관별 현행 목록 문서" 표에 추가한다. 맨 위 `마지막 갱신:` 을 오늘로.
5. `kb/index.md` 행 추가·갱신과 `마지막 갱신:`, `kb/CHANGELOG.md` 맨 위에 한 줄씩, 근거가 확인된 연결만 `kb/crossref.md` 에.
6. `kb/reports/<TODAY>.md` 를 쓰거나 이어 쓴다(UPDATE.md 5단계 형식 + 이번 클라우드 실행의 범위·판정·발견 사항·이월).

보류·기각은 UPDATE.md 2단계 표대로 처리한다(보류는 `_pending` 에 남기고 attempts +1, attempts 3 이면 기각).

## 5. 체크포인트와 PR

- 수집 끝, 검증 끝, 반영 끝마다 커밋·push 한다. 커밋 메시지는 실제 내용대로 쓴다(누가 만든 변경인지 헷갈리면 "중간 저장"으로만 적는다).
- 마지막에 PR 을 만든다. 저장소에 PR 템플릿이 있으면 그 제목 구조를 따르고, 없으면 본문에 요약·kb 반영 표(문서 | 판정)·주요 확인 사항·검증 대기·이월을 적는다. **직접 병합하지 않는다.** `kb/` 안의 변경만 있는 PR 은 `kb-check` 워크플로가 검사 후 자동 병합한다. 규칙·절차·출처·스크립트 파일을 바꾼 PR 은 자동 병합되지 않으니 사용자 승인 사항으로 보고한다. 검사가 실패하면 사유(Actions 로그)를 읽고 고쳐 다시 push 한다.
- 이미 열린 같은 브랜치의 PR 이 있으면 새로 만들지 말고 설명을 갱신한다.

## 6. 한도·오류 대처

| 상황 | 대처 |
|---|---|
| 사용량 한도로 서브에이전트 중단 | 지금까지의 `_pending` 변경을 "중간 저장"으로 커밋·push 하고, 한도 해제 후 같은 에이전트에 이어서 하라고 메시지를 보낸다(새로 띄우지 않는다) |
| 개인정보위 첨부 502 | 한 번 더 받는다. 게시물이 `pipc.go.kr`(www 없음)로 넘어가므로 첨부 주소도 같은 출처(`/np/cmm/fms/FileDown.do?...` 상대 경로)로 준다 |
| 첨부가 HWP·HWPX 만 있음 | 게시 정보만 쓰고 본문은 "원문 미확인 → 확인필요" |
| 게시판 0행 | 그 쪽만 다시 받는다 |
| 게시일과 표지 연월이 다름 | `published_date` 는 게시판 날짜, `edition` 은 자료 표기를 적고 차이를 기록한다 |
| 사용자 제공 사본(구글 드라이브)만 있음 | `sources.md` "사용자 제공 사본" 규칙: 게시판 첨부와 sha256 이 같을 때만 원문 인정, 대조 불가면 게시 정보는 확인필요 |

게시판별 쪽 넘김·첨부 주소 형식은 `scripts/browser/README.md` 와 `sources.md` 를 따른다.

## 7. 끝나면 사용자에게

1. 판정 요약표: `구분 | 건수` (수집 후보, 통과, 수정 후 통과, 보류, 기각)와 반영된 문서 목록
2. 정확성 관련 발견: 옛 조문 인용, 현행법과 다른 옛 자료, 판·시행일 차이 등
3. PR 링크(병합은 사용자 승인), 이월 항목, 접속 실패 출처
4. 로컬에서 할 일이 생겼으면(원본 보관, 에이전트 사본 복사) 한 줄로 알린다
